# Play-test guide

Everything in this repository so far was checked by tests and scripted players. Nobody has played the game by hand. This page is for the first person who does: how to run it, what to try, and how to turn the session into numbers that can be put next to the scripted player's.

## Run it
You need the .NET 8 SDK and Godot 4.7.2 (Mono).

```powershell
dotnet build game -c Debug
```

Open the `game/` folder in Godot and press F5. The game opens on the main menu. It uses Spanish or English by system language the first time; the Settings page (computer, `Tab`) switches. `F1` shows every control.

### Menus and settings
- **Main menu**: Continue (enabled when a quick save or autosave exists; it loads the newest one, whatever scenario it belongs to, and shows its play time), New game (opens the New game screen below), Settings, Controls (the key rebinding page, see [Controls](#controls)) and Quit. Arrows and Enter work as well as the mouse; `Esc` goes back from a page.
- **Pause menu**: `Esc` with nothing to cancel (no build tool, panel or selection) frees the mouse and opens it; the simulation is paused while it is open. Resume, Save and Load (the quick save, same as `F5`/`F9`), Settings, Controls, Main menu (autosaves first) and Quit. `Esc` again resumes.
- **Settings**: language, mouse sensitivity (0.5x to 2x), field of view (70 to 100), ship inertia (off, light or full: with light or full the mouse and the roll keys set a desired turn rate and the ship has angular velocity with a limited acceleration, see [flight feel](prototypes/flight-feel.md#turn-inertia-2026-11-24-client-only-replaces-the-40-ms-mouse-easing); off keeps the old 40 ms mouse easing), flight assist (damps the turn when you let go of the mouse; off = free rotation) and smooth walking and sitting (a gliding sit-down and stand-up, a soft start and stop when walking), master volume, effects, music-and-ambience and interface volume (four buses, see [audio](prototypes/audio.md); moving a slider plays a preview), invert mouse Y, fullscreen and low-quality textures (the procedural textures are generated at half size; read at start-up, so it applies the next time the game is launched). Changes apply at once and are saved to `settings.cfg` in the Godot user folder:

  ```powershell
  explorer "$env:APPDATA\Godot\app_userdata\Starfoundry Belt Prototype"
  ```

  Delete that file to go back to the defaults. Saves are in `saves\` beside it.
- **New game screen** (the main menu's New game; `Esc` goes back, `PageUp`/`PageDown` change tab) has three tabs:
  - **Campaign**: the standard game. Pick a difficulty (Relaxed, Normal, Hard, Brutal; each shows its numbers: waves to win, enemy damage and hit points, wave size and interval, time before the first wave, deposit richness, reactor output) and a galaxy seed (empty or the Random button means a random one). The goal is to survive the preset's waves, found a station and jump to another system.
  - **Story**: the seven levels as cards (the last two, Salvage Run and Hull Breach, are short challenges) (name, description, goals, difficulty, status). Level 1 is always open; each other level unlocks when the one before is completed. A completed level shows its best stars and best time. Click a card to pick it, click again (or Start) to play.
  - **Sandbox**: no goals; you set the rules. Free build on means everything is unlocked and free (the sandbox scenarios); off means materials cost and research applies (the "custom" scenarios). Threats on or off, enemy damage, hit points, wave size and interval, time before the first wave, deposit richness, reactor output, goal waves (kept in the rules, but a sandbox has no goal), the start (ship only, ship plus a blank station, ship plus a siege station), a seed and starting items (iron plate and ingot, hydrogen, carbon, ice, titanium plate, nickel plate, circuit, silicon, ammo; they go in the hold as far as it has room). Named presets are saved in `sandbox_presets.cfg` and loaded or deleted from the same tab.
- **Files** (in the Godot user folder, next to `settings.cfg`): `progress.cfg` (per scenario: completed, best time, best stars; written when a scenario is won), `sandbox_presets.cfg` (the named sandbox presets) and, beside every save in `saves\`, a `<slot>.goals` file with when each goal was done or failed, which story beats fired and whether you chose to keep playing. Without the `.goals` file a loaded game still works, but the completion times of its goals restart. All three are plain text: delete one to reset it.
- **New game screenshots**: `--newgame-shot=path [--ui-lang=es|en]` saves `path.campaign.png`, `path.story.png` and `path.sandbox.png` and quits. `--goals-shot=path` renders level 3 with the goals panel (`path.png`) and its briefing (`path.story.png`); `--scenario=<id> [--seed=N] [--difficulty=<preset>]` starts any scenario from the command line (and, like any flag, skips the menu).
- **Goal waves** are no longer a setting: the difficulty preset (or the scenario) decides how many waves must be cleared (8, 10, 12 or 15). An old `goal_waves` line in `settings.cfg` is still read and written back so the file round-trips, but nothing uses it.
- **Galaxy seed**: every new game picks a random seed (1 to 999 999 999); the pause menu shows it ("Galaxy seed: N"), the end screen lists it, the play log starts with `-- galaxy seed N` and the save header stores it, so Continue and load rebuild the same galaxy (loading a save of another galaxy while playing reopens the scene on it). `--seed=N` fixes it (and, like any flag, skips the menu). The scripted runs (every other flag: demos, screenshots, benchmarks) keep the fixed seed 20261120 so their numbers stay comparable.
- **Research panel** (the computer's Research tab: `Tab` then `2`; `Esc` or `Tab` closes): all nodes grouped as researching, available, locked and done; the selected one shows its description, progress bar, cost lines (what the lab already has out of what it needs, and what your hold has), requirements, what it unlocks (machines, recipes, belts, abilities, upgrades) and a Start button. Arrows choose, `Enter` starts, the mouse works too. A hint at the bottom says how to deliver the items (port, belt, lab). The pointer is free while it is open; the game keeps running.
- **Build menu** (`B`, `Esc` or `B` closes), docked at the right (about 40 percent of the width, down to the key panel) so the left and the centre of the view stay visible; the research tab of the ship computer docks the same way: tabs Logistics (belts, depot, ports), Production (smelter, assembler, cracker, lab), Defence (turret, wall, repair bay) and Structure (module kinds with their cost, power and purpose, and found a station). Each entry shows its quick key, cost (green when your hold can pay, red with what is missing), power use or output, a one-line description and, when locked, which research unlocks it; the detail pane under the tiles also turns a small 3D model of the machine or module (belts keep their icon). Arrows move, `Enter` or a click chooses the tool and returns you to flight with it in hand, `PgUp`/`PgDn` change tab. The old palette keys are gone: the ore, titanium, nickel, ice, quartz and carbon ports (and the cracker) are reached through the menu only. `B` now always toggles the menu, with or without a tool selected.
- **Ship thrust in the log**: steering sends thrust in steps of 64/1024 and at most ten times a second (a stop is immediate), which keeps saves small; see [structures](prototypes/structures.md#limits). `--load-bench` measures it.
- **Icons and the shared look** ([ui-icons](prototypes/ui-icons.md)): `Gallery.tscn --focus=icons --shot=out.png [--lang=es|en] [--page=1..3]` shows the whole icon set with names; `--ui-shot` also saves `path.research.field.png`.
- **Agent play** ([agent play](prototypes/agent-play.md)): `--agent` keeps the game flying and reading keys without the OS window focus and keeps the main menu, so an agent can drive a throwaway copy (`tools/agent/`); `--structure-demo --demo-orbit=<deg/s>` orbits the camera for movies.
- **Window size for shots**: `--window=WxH` (for example `--window=1024x600` or `1280x720`) puts any scripted run or screenshot in a window of that size; without it the shots use the maximised window, so small screens were never checked. Notifications carry a small icon of their category (threat, production, logistics, info).
- **Text-fit audit**: `powershell -ExecutionPolicy Bypass -File tools/ui-audit.ps1` runs `--ui-audit` (in game, campaign and a scenario) and `--ui-audit-menu` for es and en at 800x600, 1024x600, 1280x720 and 1920x1080 and fails when any text overflows, is cut without a tooltip or overlaps; see [ui-icons](prototypes/ui-icons.md#the-text-fit-audit). Build tiles wrap their names to two lines and shrink the font before cutting. The audit also has a timing pass (vsync off): per step it prints `UIAUDIT PERF ... open=..ms worstFrame=..ms` and fails at 1920x1080 when a panel takes over 100 ms to open or two frames of one step go over 20 ms (one slow frame is a note: a hitch).
- **UI screenshots**: `--ui-shot=path [--ui-lang=es|en]` saves `path.research.png`, `path.research.locked.png`, `path.build.png` (Production tab), `path.build.logistics.png`, `path.build.structure.png`, `path.build.defence.png` (the panels docked at the right, with the key panel under them) and `path.bar.png` (the bottom strip and the key panel with a tool in hand), then quits. `--keys-shot=path [--ui-lang=es|en] [--keys-size=1920x1080]` saves the key panel in six contexts (`path.flying.png`, `.build.png`, `.aim.png`, `.walking.png`, `.map.png`, `.menu.png`) plus `.research.png`, `.help.png` and `.info.png` (seated, info panels open), at 1280x720 unless told otherwise.
- **Weapons and the shipyard** ([weapons and shipyard](prototypes/weapons-shipyard.md), [ADR 0032](adr/0032-weapons-as-hardpoint-modules-and-the-shipyard.md)): the ship mines and shoots with hardpoint modules. The starter ship has a mining laser on its nose and a gun on top of the cockpit; without a laser module the laser cannot be taken ("fit one at a shipyard"), without a gun module `M` cannot pick the guns. `M` switches the weapon in hand (no stow or deploy step; the HUD names it and the key panel says what the click does): the mining laser (hold the click on a deposit within the laser's reach, 10 cells from the module, 14 for the Mk2) or the guns (hold the click: they fire along the crosshair whether or not there is an enemy, see [weapons feel](prototypes/weapons-feel.md)). Each laser module draws its own beam from the tip of its emitter, mines the same deposit faster (two Mk1 lasers double the rate, a Mk2 counts 425 percent against the Mk1's 250) and draws 5 power (Mk2: 8). Build a **shipyard** module at a station (`N`, cycle to Shipyard; 24 iron plates, 16 iron ingots, 8 carbon), dock the ship (`F` at a port) and open the computer (`Tab`, Designer tab): the ship designer shows the ship's grid layer by layer (`Capa -` and `Capa +` change the height; bow at the top), a spinning 3D preview and the module list. Pick a kind and click a free cell next to the ship to add it; click a module to select it and remove, move or upgrade it (laser or gun to Mk2). The panel says whether the design is valid and what it costs (the hold pays first, then the station stock; a removed module refunds half, a moved one is free) and `Aplicar diseño` / `Apply design` sends it in one command. A design needs a cockpit, an engine, a reactor and a cargo module, one connected piece, the docked port kept, and nothing removed that holds a machine. Headless check: `--designer-shot=path` saves the designer (`path`), the applied design (`path.applied.png`) and the refitted ship (`path.ship.png`); `--laser-shot=path` saves two lasers mining a rock (`path`, `path.cockpit.png`).
- **Weapons feel** ([weapons feel](prototypes/weapons-feel.md), [ADR 0036](adr/0036-free-fire-recoil-hold-overflow-and-resource-density.md)): `1`-`9`, `V` and the wheel pick the weapon in hand from the arsenal bar (ADR 0036 had `M`, which is the map now), the left click fires it. With the guns in hand a barrel and a faint guide along the crosshair show where they point; hold the click and tracers fly from the nearest gun to where the crosshair meets something (a rock, a mine, debris, an enemy) and leave sparks; mines blow up and debris breaks apart when shot, from a distance if you pick it (a mine arms when a module is within about 17 cells). The Mk1 gun has no recoil; the Mk2 kicks the camera and pushes the ship a little. Settings has an optional "Aim assist" (an enemy within five degrees of the crosshair is aimed at). Check: hold the click on a rock; mine with a full hold and watch the ore float; empty a rock, fly 200 cells away and come back after twelve minutes to find a small one regrown; look at `--gun-shot=path` (tracers with no enemy: `path`, `path.impact.png`, `path.outside.png`) and `--overflow-shot=path` (a full hold breaking a rock: `path`, `path.outside.png`). Normal and Relaxed galaxies hold more deposits (resource density 140 and 150 percent; `--density=N` on the scripted player).
- **New materials and wrecks** ([materials](prototypes/materials.md#materials-and-what-they-are-for-audit-and-the-optional-chains-2026-11-24)): fly slowly (under 20 units a tick) within 12 cells of a derelict wreck for a second and its loot goes into the hold; some wrecks hold resonant crystals, which nothing else gives. Research Composites, Cryogenics and Resonance (Research tab) for carbon fibre, composite plates, coolant and focus lenses; the Mk2 laser asks for a lens and coolant, the Mk2 gun for a composite plate and coolant. The crystal port (build menu, Logistics) carries crystals from the hold onto a belt.
- **Flight feel** ([flight feel](prototypes/flight-feel.md), [ADR 0033](adr/0033-flight-inertia-solid-deposits-and-hit-volumes.md)): the ship has inertia. The thrust sets the speed you ask for and the ship follows it: about 1.2 s to the top speed of one engine (6 cells a second) and 0.6 s to stop; boost (`Shift`, 400 percent) raises the top speed and the acceleration with it, so 24 cells a second takes about as long. Releasing the keys brakes; a ship that rams a rock loses the speed into it. The speed card (top centre) shows the real speed against what the engines can do now and a gauge: the fill is the real speed, the white tick the speed the thrust asks for. Two rings on the view show where the ship is going (green, wings) and where it came from (amber, cross): to stop, turn the nose to the cross and thrust. The dust streaks stretch with speed, the view widens a few degrees and the engines rumble a little with speed and boost, the flame grows with the push and the engine sound rises. The rock of a deposit is solid now (the ship stops against it and takes a small hit above 10 units a tick), the same as an asteroid; rocks and debris are hit by their drawn size plus half a cell of hull padding. Mine from beside a rock: the laser reaches 10 cells from its module (14 for the Mk2). A station cannot be founded or extended inside a deposit's rock ("There is a rock of ore there"). Three research nodes raise the engines: ion thrusters (top speed +25 percent), thrust vectoring (acceleration +40 percent, after carbon processing) and, with engineering science, the plasma drive (+35 and +40); the ship designer shows the layout's engines, top speed and time to reach it. Headless checks: `--measure-models` prints how far every rock, mine, wreck and deposit model reaches from its centre (the hit sizes come from it); `--obstacle-shot=path --obs-scene=ramp|cruise|boostcruise|brake` saves the cockpit with the speed card, `depositrock` and `rockmargin` save a ship resting on a rock and print the distance from the drawn rock to the module boxes.
- **Docking** ([docking](prototypes/docking.md)): the ship moves, a station is fixed. A station (core), a dock module and the ship's cockpit flanks have docking ports. Fly slowly towards a free port of your station: within 45 cells the port shows a marker, its collar a ring of guide lights, and the key panel adds `F` with the distance and your speed against the docking limit. `F` from afar starts the assisted approach (the autopilot flies you to the port, slows down and docks; flying by hand or `F` again cancels it); inside 12 cells, slower than a quarter of the engine speed (the real speed: a ship that still coasts is too fast) and lined up with the port (within about 15 degrees of its axes) it docks at once; a ship that is tilted gets the assisted approach instead, which turns it onto the port's axes on the way in. Docked, the ship is locked to the port (no thrust, no jump), the airlock opens between the two modules and you can stand up and walk into the station; the station's stock shows in the key panel. `,` unloads the hold into the stock (not the fuel), `.` loads from it (fuel first), `F` undocks (aboard the ship; the autopilot pushes off along the port's axis). While docked the reactor burns the stock's hydrogen, the ship repairs three times as fast and the station's shields and defence modules cover it. A station takes no cockpit and no engine. Headless check: `--dock-shot=path` saves `path` (the approach), `path.approach.png`, `path.cockpit.png`, `path.docked.png` (from outside), `path.walk.png`, `path.airlock.png`, `path.station.png` and `path.hud.png`.
- **Items on the ground** ([ADR 0038](adr/0038-dropping-items-and-picking-them-up-by-hand.md)): drag a stack out of the inventory window (`Tab`, `I`) and release it over the world to drop it (a small tinted crate lands in front of you, ahead of the ship when seated, and stays 30 minutes); aim at a crate for its name and count and press `F` to pick it up (on foot within 3 cells, seated within about 12). Bag first, then the hold. Check: `--drop-shot=path` (`path` the cockpit, `path.outside.png` three crates with the tooltip).
- **Personal inventory** ([inventory](prototypes/inventory.md), [ADR 0035](adr/0035-personal-inventory-container-moves-and-reactor-fuel-slots.md)): `I` (or `F` or a click on a reactor, or the Inventory tab of the computer) opens your bag of 24 slots beside the ship hold, the stock of a station you are docked at or close to, a reactor or a machine you aim at. Drag a stack from slot to slot (right button: half), Shift click or double click moves it to the other panel, Sort packs the bag, the filters dim what is not ore, parts, fuel or ammo, the bin asks before it throws away. A reactor has a fuel slot: drop hydrogen or fuel cells in it and it burns them first, with the burn time under the slot; its auto-feed selector (none, from the hold, from my inventory, hold then inventory) says where it takes more from when the slot is empty (the hold is the default, as it always was). Try: take 10 fuel cells from the hold to the bag, put them in the reactor, choose "none" and watch the hold stay untouched. Old saves (before log version 18) say the inventory is not available. `--inventory-shot=path [--ui-lang=es|en]` saves the panel at 1280x720 and 1920x1080 (`path.<size>.<lang>.reactor.png`, `.hold.png`, `.machine.png`, `.bin.png`).
- **Space atmosphere**: there is no floor grid any more. The sky is procedural (`game/Ambience.cs`) and comes from the system seed: a nebula band with dark dust lanes, three star layers, a sun disc with a lens streak (the directional light matches it), a far giant star, and two distant bodies lit by that sun (a banded gas giant, often ringed, and a small world). Specks of dust hang around the ship for parallax, a faint haze tints the distance, and above a cell per second thin motion streaks fade in along the direction of travel and stretch with the speed (long lines at boost); they are built from the velocity vector, so they converge on the heading in every attitude (`--streak-shot=path` checks it). The mouse turn and the roll ease in and out a little, so the controls feel fluid. With a cell build tool in hand, a faint 9x9 patch of cell lines shows under the aimed cell, and only on the floor of a fabrication bay (ADR 0031). Look at it with `--structure-demo --demo-big --shot=out.png` or any `--*-shot`.
- Any command-line flag (`--demo`, `--shot=`, `--hud-shot=`, `--structures-shot=`, `--stress=`, `--save-test` and the rest) skips the menu and starts the game directly, as does running `Play.tscn` from the editor. `--menu-shot=path` saves the main menu (`path`), the Settings page (`path.settings.png`), the Controls page (`path.controls.png`) and the pause overlay over the game (`path.pause.png`), then quits. The materials of every model are procedural textures ([materials](prototypes/materials.md)); `Gallery.tscn --focus=materials` shows them all, and `--focus=framing` shows how the module plating frames its panels on a cube, a chamfer, a drum and a strip of modules.

## Controls
A short fixed core, one ship computer for everything else (design: [controls redesign](superpowers/specs/2026-11-25-controls-redesign-design.md)). `F1` lists them all, generated from the same table as the key panel.

| Key | Does |
|---|---|
| `W` `A` `S` `D`, `Space` `C`, `Shift` | fly along the ship's axes (or walk), up and down, boost (run on foot) |
| mouse | turn the ship, or look; left click uses what you carry (fires, places, picks), right click demolishes with a tool |
| `Q` `E` | roll the ship (with a module tool: change layer; in the computer: switch tab) |
| `F` | interact: sit and stand, climb a ladder, dock and undock, open the machine, reactor or shipyard you aim at, change the workbench recipe, look at a cockpit display, assign drones to a deposit |
| `Z` | flight assist on and off |
| `1`-`9`, `V`, wheel | the arsenal: pick a slot of the bar at the bottom centre (lasers, then guns), or step through them (`V` next, wheel either way; in the ship computer the wheel zooms) |
| `K` | scan |
| `Tab` | the ship computer: Map, Research, Inventory, Build, Info, Designer (docked at a shipyard), Settings, Systems; `Q` `E` or `1`-`8` change tab, `Tab` or `Esc` closes it |
| `B` `I` `M` | the computer on the Build, Inventory or Map tab |
| `H` | cycle the HUD detail level |
| `R` `Y` `N` | with a build tool: rotate belts, change recipe, module kind |
| `F1`, `F5`, `F9`, `F11`, `Esc` | help, quick save, quick load, fullscreen, cancel / close / pause menu |

**Rebinding.** Every key can be changed in *Controls* (main menu and pause menu) or in the ship computer's Settings tab, button *Keys and shortcuts*. Press *Rebind* on an action, then the new key (`Esc` cancels); *Clear* leaves an optional action without a key, *Reset* restores one action and *Reset all* restores everything. A key that another action already uses *at the same time* (flying and walking never overlap, but flying and the always-on keys do) opens a *Swap* or *Cancel* dialog. `Esc`, `F1` and `Tab` are reserved, and mouse buttons, the number rows (weapon, build and tab picks) and the computer key are fixed. The keys are saved in `settings.cfg` as `bind.<action>=KEY1,KEY2`; the key panel and `F1` show your keys. Details: [key rebinding](prototypes/key-rebinding.md). `--rebind-shot=path` saves screenshots of the page.

The computer keeps the simulation running (only the pause menu stops it). Speed, pause, drone assignment and the cockpit display focus are in its Systems tab; language, volumes and the HUD mode are in Settings; repair and remove are buttons on a machine's panel; the hold's spare-ore dump is a button in Systems.

## The first ten minutes
1. Follow the steps (full list under `H`; for the first three steps a one-line "Next: ..." hint also shows above the hold bar and fades away afterwards; with the mining laser out and nothing aimed the line says how to aim it). Each one ticks off by itself.
   The game is played in first person: the mouse steers the ship (the cursor is captured): pitch and yaw about the ship's own axes with no limit, and `Q`/`E` roll it, so you can fly upside down and nothing says which way is "straight" (see [free flight](prototypes/free-flight.md)); `W`/`S` fly along the ship's axis, `A`/`D` strafe, `Space`/`C` go toward the ship's roof and floor. With a build tool in hand, or with `Alt` held, the mouse looks around inside the ship instead (upright in the ship's own frame). (`W`, `A`, `S`, `D`, `Space` and `C` are read as physical keys, so they sit in the same place on AZERTY and other layouts; every other key follows the layout). `Tab` opens the ship computer and frees the cursor (it is captured again when you close it); `Esc` leaves a build tool, then opens the pause menu. The top-down camera is gone. `F` stands you up from the pilot seat; standing, `F` at a ladder climbs between decks (look up or down to choose), `W`/`A`/`S`/`D` walk inside the ship (`Shift` runs, no jump, `Space`/`C` unused), flight and the autopilot (`M`) are off, and `F` near the seat sits you down again. Repair is a button on a machine's panel. Walking is client-only and limited to your own ship (see [structures](prototypes/structures.md)). Ships come in a few section shapes (a wide pilot section, plain, arched and boxy hull sections with pillars), joints are closed and the furniture of every module kind, the machines and the workbench are solid; belts and floor plates can be walked over (see [structures](prototypes/structures.md#shell-variety-closed-joints-and-solid-furniture-2026-11-24)). Model and collision audits: `Gallery.tscn --focus=ship-starter|ship-nose|ship-row|ship-big|ship-tower|ship-skins|station-demo --audit=holes|coplanar|walk|floating|glass|all [--step=1.0]` prints `AUDIT` lines (holes in the skin, overlapping faces that flicker, solids the body walks through). Headless check: `--walk-shot=path`; add `--walk-bevel` to walk the body into the floor and ceiling bevels, door frames and the nose of the ship's modules (prints `BEVEL` lines and saves `path.bevel.<kind>.<step>.png`).
2. You start seated in the starter ship (cockpit, hull, cargo, reactor, engine; 20 hydrogen for the reactor). It has **no factory and no buildable module**: only a workbench (`F`) and the hold ([ADR 0031](adr/0031-construction-rules-fabrication-bays-and-floor-building.md)). Fly to the brown rock (WASD) until it is within 6 cells, make sure the mining laser is the weapon in hand (`1`, or `M` to cycle), aim the crosshair at the rock and hold the left click: the beam mines by hand at 2 ore per second for as long as you hold it and stay aimed and in range (let go, look away or fly out of range and it stops). The ore goes into the hold. Press `F` to switch the workbench on: it turns ore into ingots (2 s each), press `F` again for plates (2 ingots each, 2 s) and once more for ammo (1 ingot for 4 rounds), and a fourth time to stop it; it makes one thing at a time and the ore, ingot and plate counts move in the hold. Hand mining pauses on its own when the hold reaches 75 % (45 of 60), so there is room to craft and to build; the game says so with a toast and a status line. Spend or move items to continue (there is no command to discard items yet).
3. Make 24 ingots and 8 plates with the workbench, press `N` until the module tool says *Fabrication bay* (24 ingots and 8 plates), aim at a face of the ship beside the hull and click: this is where the factory goes. On its floor (open the build menu with `B`) put an ore port, a smelter, an assembler and a depot and join them with belts; machines and belts are built only on the floor of a fabrication bay (or of a station core, or turrets and walls on the floor of a defence module), and the ghost shows why a cell is refused. Right click on a machine or a belt demolishes it. When the first plate comes out of the assembler (step 5), press `I`, aim at the space beside the ship (the green volume means it can be founded) and click to found a station: it starts with a core module and costs 16 ingots and 12 plates from the hold. A station has no power of its own: add a Reactor module (`N` picks the module tool, pressing `N` again changes the kind) and keep hydrogen in the hold.
4. Open the build menu (`B`): Production has the smelter, assembler, hydrogen cracker and research lab, Logistics has the belts and the ports (ore, ice, quartz, carbon, cargo), Defence has turrets, walls and the repair bay, Structure has the modules (the Fabrication bay is the one that lets you build). Hydrogen is made by a cracker fed ice by an ice port (mine ice by hand first). Look at the ground and the crosshair picks the cell (red when you cannot place there); click to place, for belts press, move the crosshair and release. Right click demolishes a machine or a belt (aim at it, at any height), `R` rotates, `Y` changes the recipe. There is no layer to choose: the ghost snaps to the floor of the bay under the crosshair. Click a machine with no tool, or press `F` on it, to see its status and use its buttons.
5. Build a research lab, feed it plates by belt from an assembler (a port cannot hand out plates), open the computer (`Tab`) on its Research tab and start Logistics: it lists the cost, what the lab already has, what is required and what it unlocks. Ports are free in structure worlds, so research is about belts, defence upgrades, the jump drive and the advanced materials.
6. When the warning says a wave is coming, turrets can only be built inside a Defence module: add one with `N`, place a turret in it (Defence tab of the `B` menu, or `8`), feed it ammo by belt from an ammo assembler and switch your weapon on (`V`). Each jump to another system (`M`, then `Enter`) costs 5 carbon from the hold, so mine carbon before you leave.

## The goal and the end
The last line of the steps panel is the goal, pinned even when the list is folded: "Goal: survive 10 waves with a station and visit another system (waves N/10, jumps Y/1)". A wave counts as survived once every enemy of it is dead; the goal also needs a station of yours standing (found one with `I` before the last wave) and one completed jump, so the jump drive has to be researched and a second system visited: the research path is part of the win. Until the jump is done, the line adds a hint once the waves are cleared.

- **Victory** ("Station secured"): the goal is met. The game pauses and shows the play time, modules built, stations founded and lost, waves survived, what was mined by hand and by drones, and what was lost. It writes an extra `victory` save. Buttons: Keep playing (endless, the screen never comes back), Main menu, Quit.
- **Scenario games** (everything started from the New game screen): the steps panel at the top right starts with a goals section instead of the goal line: each goal has a small icon of what it asks for (the item, the module, the research node or a status symbol); primary goals with a ring (a bar with `current/target` where it counts something), secondary goals with a star, a countdown for goals with a time limit (red under a minute), a failed goal in red with a cross. The guided steps stay under it for the campaign and the levels, and are hidden in a sandbox (free build) without goals. The first story beat of a level opens as a briefing (the scenario's briefing, who is speaking and what they say; the game pauses until you press Intro/Enter); later beats are toasts with the speaker's name. Scenario games end by the scenario's own rules, not the plain wave count:
  - **Victory**: the title, the scenario name, the stars (1 for a win; 2 with the primary goals inside the time bound or with the secondary goals the level asks for; 3 with all of it), a hint for the next star, your time against the best (new record or first completion), each goal as done or failed, and the usual numbers. Buttons: Next level (story levels), Keep playing (campaign, sandbox and custom only; the screen does not come back), Main menu. Winning writes `progress.cfg`; the story levels do not write a `victory` save.
  - **Defeat**: the ship is lost, a primary keep goal failed or a primary time limit passed. Buttons: Retry (the same scenario, rules and seed), Load last save, Main menu. Your autosave and quick save are untouched.
  - Loading a save of another scenario (F9 or the pause menu) reopens the scene on it, like a save of another galaxy. `--end-shot=path` renders a made-up two-star win and a real loss on level 3 (add `--end-legacy` for the old wave-count overlays).
- **Defeat** ("Ship lost", old saves and scripted worlds): the ship's last cockpit fell (there is no respawn in the structures campaign). The play log gets an `Outcome` line. Your autosave and quick save are untouched (a lost world is never autosaved), so Load last save takes you back; or New game, or Main menu (which does not autosave).
- Screenshots of both overlays: `--end-shot=path` saves `path.victory.png` (made-up numbers) and `path.defeat.png` (a real loss).

While a structure is under attack: modules darken and redden with their damage and, below half, throw sparks and smoke with a flickering light; a hit flashes the module and, if it is your ship's, a red vignette pulses; the status block shows the ship's integrity bar; a wave countdown and then the enemy count are shown large at the top; a module you aim at (or one hit in the last seconds) shows its hit points; losing a module or a station raises a toast and an explosion. `--defence-shot=path` renders these (`path`, `path.cockpit.png`, `path.destroyed.png`, `path.station.png`).

## What to try after that
- Hand mining slows to a quarter past 75 percent of the hold and, when the hold is full, still breaks the rock: the ore that does not fit floats beside it as pickups (a toast says so once per rock) that the ship pulls in from about six cells away once there is room, and that fade after three minutes. Drones still wait at 75 percent. The Systems tab button throws the largest stack of spare ore (carbon beyond the jump cost, quartz, titanium or nickel ore, ice while hydrogen is at least 20) into space, with a toast; check that mining resumes afterwards and that iron and hydrogen are never dumped.
- Walls (`9`) in front of the base and the repair button during a wave; a repair bay (`0`) fed ingots by belt.
- The defence upgrades in the research tab (`Tab`), the ports of the Logistics tab of the build menu (`B`; ore, titanium, nickel, ice, quartz and carbon ports are menu-only) and the jump to another system (`M`, then `Enter`) when the status panel says the home ore is running low.
- Play at your normal pace and do not read the docs: where you get stuck is the finding.

## Hints
After the sixteen guided steps (docking, salvaging a wreck and fitting a second weapon were added in 2026-11-24) (the panel then says what comes next: scout other systems, get titanium and quartz, build drones, defend) the game teaches the rest with hints that appear when the situation happens, once each and at least 25 seconds apart, as long messages at the bottom: turrets without ammo during a wave, damaged machines (repair from the machine's panel), the first loss without walls, an idle lab, the defence upgrades once Logistics is done, the cargo port once the jump drive is researched and the home ore is low, a station with machines but no Reactor module (`BeltNetwork.StationHasNoReactor`), 15 or more of an ore in the hold with no port for it (structure worlds), and the 5-carbon cost of a jump the first time you open the star map without it. Each hint shown is a `Tip` line in the play log. If a hint came too early, too late or not at all, that is worth noting.

## The HUD
The first-person HUD is minimal by default and shows information by context, never all at once. On screen at rest: the crosshair, the key panel, the notifications and (only when a wave warning or enemies are on) a small alert at the top. Everything else fades in when the context asks for it and fades out again:
- **Seated or flying:** the ship card (top left: hull bar when there are threats, flight readiness, power and hydrogen fuel, structure integrity), the flight readout (top centre: the galactic-frame gizmo, the fixed X, Y, Z axes of the galaxy as seen from your ship, which is not a horizon, and the speed in cells per second; there is no compass: space has no up), the hold strip (bottom left: bar and item counts) and the 3D markers (the selected deposit and the two nearest others, the nearest enemy, stations and docking ports, and the gate toward the system chosen on the star map, each with a name and a distance; off screen, an arrow on the screen edge points the shortest way to turn and says how many degrees).
- **Arsenal bar (bottom centre, seated):** one numbered slot per weapon kind and mark fitted (mining laser Mk1/Mk2, gun Mk1/Mk2) with the module count, a state ring (ready, firing, cooling, out of reach, low or no power, no ammo), the mining readout (items per second, what is left in the deposit) or the volley state under the slot in hand, and a marker that eases to the slot you pick. All the lasers act together and all the guns act together, so a second slot of the same group is outlined as "acts together". It fades after about four calm seconds and comes back on a switch, a shot, a wave or enemy, or with the ship computer open (click a slot there). Minimal detail shows only the slot in hand; the cockpit-only and minimal HUD modes, a build tool in hand, and standing leave it out (the cockpit weapons page lists the same slots). Check: `--arsenal-shot=path` saves `.laser`, `.ease`, `.gun`, `.firing`, `.minimal`, `.cockpit` and `.outside` pictures of a ship with two Mk1 lasers, a Mk2 laser and a Mk2 gun (run it at `--resolution 1280x720` and `1920x1080`, `--ui-lang=es|en`); see [arsenal](prototypes/arsenal.md).
- **Standing:** nothing but what you aim at. The ship card only appears during a threat. Enemy markers still show.
- **Aiming at something:** that object's card next to the crosshair. A machine gets the target panel (name, role, status, recipe, power, hit-point bar; click it to pin it in the inspector); a belt or a deposit gets a small card with its details; a damaged module shows its hit points. The ship card and the flight readout step aside while you aim at an object.
- **A build tool in hand:** the tool and its cost (bottom left, green when affordable, red when short, grey when locked), the one-line hint and the placement card at the crosshair.
- **The Info tab of the ship computer (`Tab`).** One toggle opens everything the screen normally hides: the full status block (selected deposit, system, threat noise, research, upgrades, structure power), the goals and guided steps (top right) and the hold. The steps button folds the steps inside it.
- **HUD mode (Settings tab of the computer, or the button on a cockpit display; saved in the settings).** `Full` is everything above. `Cockpit only` hides, while you sit, the ship card, the world markers, the speed and galactic-frame readout and the hold strip: the [cockpit displays](prototypes/cockpit-displays.md) on the console carry that information, and the crosshair, the key panel, the alert and the notifications stay. `Minimal` also drops the key panel. Standing, a mode never hides what walking and building need (cockpit-only keeps the whole overlay; minimal drops the key panel). `H` (the info panels), a build tool in hand and a menu being open always show what they need, and looking at a display (`F` on the console) hides the outside cards and markers for as long as you look. The row in the key panel says which mode is on; the choice is `hud_mode` in `settings.cfg`.
- **Cockpit displays (`F` on the console, or click a screen).** Three emissive screens on the pilot's console show the flight (speed, thrust, boost, hull, power, hydrogen, hold, attitude and velocity), navigation (the system, a list of deposits, the nearest enemy, the port and the gate with distance and the degrees to turn; select, autopilot to the chosen deposit, assisted dock approach, scan), systems (the same gauges, the modules as a row of cells, the threat) and weapons (laser and guns, the weapon group, mining) pages. Hold `Alt` to look at the console without steering, put the crosshair on a screen and click a button (a tab changes the page, and picking a page that is on another screen swaps the two); a click on a screen without a button moves the view in on it, and with it in focus the mouse moves the view over the screen, left and right change screen, up and down change page, and `F`, `Esc` or the right button leave. Screens are small from the seat at rest: they are meant for glances (the big numbers) and for focus. The nav page leads with the target name, distance and speed in large type and has a map of the ship's surroundings (deposits, threats, port, gate as icons, a dashed route to the chosen target); with the nav display in focus the wheel zooms the map, a left drag turns it and a click on an icon or a list row picks that target (ports and the gate too). Looking at a screen for about 0.4 s with the mouse still frames it gently; moving, flying ends that. The flight display shows the turn rate on three axes and an assist button; a reactor short of power dims the screens. See [cockpit displays](prototypes/cockpit-displays.md#navigation-screen-and-the-larger-console-2026-11-24).
- **HUD detail (`H`, the button on every cockpit display, or the Settings page; saved as `hud_detail`).** On top of the mode, three levels say how much each family says; the study behind them is [hud-information-study](prototypes/hud-information-study.md). *Standard* (default) is the HUD of old plus a target card under the ship card (the nearest enemy with distance, closing speed and hull, or the deposit you mine or chose with what is left and how far), the weapon row in a fight, the shield row when there is a shield, and a forecast chip in the hold strip ("full in 2:10") while the hold grows. *Minimal* keeps the vitals: the ship card shows hull and fuel (the power gauge and the integrity bar only when something is wrong), the flight card only the speed number, no hold strip while flying, and the key panel drops the rows of the actions you learn in the first minutes (alerts, lit rows, the seat, docking, help and the HUD key stay). *Detailed* adds the brownout-risk row ("demand above supply", "fuel for 3:10"), the damaged-module count, the income per minute next to the hold forecast, the current guided step with its progress bar under the ship card, and an arrow for each of the three nearest threats. At most 7 groups show at once at any level; the context (flying, mining, walking, building, docked, combat) decides which: a table is in the study. Nothing but markers and the aim card enters the centre 30 percent of the screen, and the toast stack stops above it.
- **Interface feel.** Every button glows on hover and dips on press (about 100 ms), panels fade and grow in, gauges and the hold numbers ease to their new value, and a press on a disabled button wobbles. Menus and HUD buttons click at the press (not the release) and tick very quietly on hover; both sounds can be turned off on the Settings page (`ui_click_sound`, `ui_hover_sound`). The HUD cards refresh at most 15 times a second, or at once when the context or the level changes.
- **Cockpit displays (`F` on the console, or click a screen).** Three emissive screens on the pilot's console show the flight (speed, thrust, boost, hull, power, hydrogen, hold, attitude and velocity), navigation (the system, a list of deposits, the nearest enemy, the port and the gate with distance and the degrees to turn; select, autopilot to the chosen deposit, assisted dock approach, scan), systems (the same gauges, the modules as a row of cells, the threat) and weapons (laser and guns, the weapon group, mining) pages. Hold `Alt` to look at the console without steering, put the crosshair on a screen and click a button (a tab changes the page, and picking a page that is on another screen swaps the two); a click on a screen without a button moves the view in on it, and with it in focus the mouse moves the view over the screen, left and right change screen, up and down change page, and `F`, `Esc` or the right button leave. Screens are small from the seat at rest: they are meant for glances (the big numbers) and for focus.
- **Notifications:** at most three at a time, repeats grouped as "x3", coloured by category (green production, amber logistics, red threat, white info).
- **Key panel (bottom right):** a compact column of `[KEY] label` rows, drawn as key caps, that changes with what you do or aim at (table below). With the mouse free (`Tab` opens the computer, or `F` on a machine) a row is clickable and presses its key; the row of the active tool or menu is highlighted, an unavailable row is dimmed and says why in its tooltip (for example "drone bay locked"), and the `1-0` row lists the quick keys with their costs in its tooltip. ## Saving
`F5` saves to the quick slot, `F9` (and Load in the pause menu) loads the newest of the quick save and the autosave, the same rule as Continue in the main menu, and a played game saves itself to an autosave every five minutes of real time. A save is written to a temporary file and renamed over the slot, so a crash mid-save cannot corrupt it; the previous contents are kept beside it (`quicksave.bak.sfsave`, and `autosave.prev.sfsave` for the autosave, so a new game's first autosave does not destroy the previous game's one). A failed load says why in a toast (made with other content, corrupt or not found). The files are in the `saves` folder next to `playlogs` (`%APPDATA%\Godot\app_userdata\Starfoundry Belt Prototype\saves`). A save is the log of what you did and is replayed when loaded, which takes a second or two for an hour-long base ([ADR 0016](adr/0016-saves-are-the-command-log-replayed.md)). If the game says a save cannot be loaded, keep the file and tell me: it means the game changed since it was made. After a load the guided steps are recomputed and a hint may show again. The play log notes the load.

## Sound
