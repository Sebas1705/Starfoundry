# Play-test guide

Everything in this repository so far was checked by tests and scripted players. Nobody has played the game by hand. This page is for the first person who does: how to run it, what to try, and how to turn the session into numbers that can be put next to the scripted player's.

## Run it
You need the .NET 8 SDK and Godot 4.7.2 (Mono).

```powershell
dotnet build game -c Debug
```

Open the `game/` folder in Godot and press F5. The game opens on the main menu. It uses Spanish or English by system language the first time; `L` (or the Settings page) switches. `F1` shows every control.

### Menus and settings
- **Main menu**: Continue (enabled when a quick save or autosave exists; it loads the newest one, whatever scenario it belongs to, and shows its play time), New game (opens the New game screen below), Settings, Controls (the same text as `F1`) and Quit. Arrows and Enter work as well as the mouse; `Esc` goes back from a page.
- **Pause menu**: `Esc` with nothing to cancel (no build tool, panel or selection) frees the mouse and opens it; the simulation is paused while it is open. Resume, Save and Load (the quick save, same as `F6`/`F9`), Settings, Controls, Main menu (autosaves first) and Quit. `Esc` again resumes.
- **Settings**: language, mouse sensitivity (0.5x to 2x), field of view (70 to 100), master volume, effects, music-and-ambience and interface volume (four buses, see [audio](prototypes/audio.md); moving a slider plays a preview), invert mouse Y, fullscreen and low-quality textures (the procedural textures are generated at half size; read at start-up, so it applies the next time the game is launched). Changes apply at once and are saved to `settings.cfg` in the Godot user folder:

  ```powershell
  explorer "$env:APPDATA\Godot\app_userdata\Starfoundry Belt Prototype"
  ```

  Delete that file to go back to the defaults. Saves are in `saves\` beside it.
- **New game screen** (the main menu's New game; `Esc` goes back, `PageUp`/`PageDown` change tab) has three tabs:
  - **Campaign**: the standard game. Pick a difficulty (Relaxed, Normal, Hard, Brutal; each shows its numbers: waves to win, enemy damage and hit points, wave size and interval, time before the first wave, deposit richness, reactor output) and a galaxy seed (empty or the Random button means a random one). The goal is to survive the preset's waves, found a station and jump to another system.
  - **Story**: the five levels as cards (name, description, goals, difficulty, status). Level 1 is always open; each other level unlocks when the one before is completed. A completed level shows its best stars and best time. Click a card to pick it, click again (or Start) to play.
  - **Sandbox**: no goals; you set the rules. Free build on means everything is unlocked and free (the sandbox scenarios); off means materials cost and research applies (the "custom" scenarios). Threats on or off, enemy damage, hit points, wave size and interval, time before the first wave, deposit richness, reactor output, goal waves (kept in the rules, but a sandbox has no goal), the start (ship only, ship plus a blank station, ship plus a siege station), a seed and starting items (iron plate and ingot, hydrogen, carbon, ice, titanium plate, nickel plate, circuit, silicon, ammo; they go in the hold as far as it has room). Named presets are saved in `sandbox_presets.cfg` and loaded or deleted from the same tab.
- **Files** (in the Godot user folder, next to `settings.cfg`): `progress.cfg` (per scenario: completed, best time, best stars; written when a scenario is won), `sandbox_presets.cfg` (the named sandbox presets) and, beside every save in `saves\`, a `<slot>.goals` file with when each goal was done or failed, which story beats fired and whether you chose to keep playing. Without the `.goals` file a loaded game still works, but the completion times of its goals restart. All three are plain text: delete one to reset it.
- **New game screenshots**: `--newgame-shot=path [--ui-lang=es|en]` saves `path.campaign.png`, `path.story.png` and `path.sandbox.png` and quits. `--goals-shot=path` renders level 3 with the goals panel (`path.png`) and its briefing (`path.story.png`); `--scenario=<id> [--seed=N] [--difficulty=<preset>]` starts any scenario from the command line (and, like any flag, skips the menu).
- **Goal waves** are no longer a setting: the difficulty preset (or the scenario) decides how many waves must be cleared (8, 10, 12 or 15). An old `goal_waves` line in `settings.cfg` is still read and written back so the file round-trips, but nothing uses it.
- **Galaxy seed**: every new game picks a random seed (1 to 999 999 999); the pause menu shows it ("Galaxy seed: N"), the end screen lists it, the play log starts with `-- galaxy seed N` and the save header stores it, so Continue and load rebuild the same galaxy (loading a save of another galaxy while playing reopens the scene on it). `--seed=N` fixes it (and, like any flag, skips the menu). The scripted runs (every other flag: demos, screenshots, benchmarks) keep the fixed seed 20261120 so their numbers stay comparable.
- **Research panel** (`T`, `Esc` or `T` closes): all nodes grouped as researching, available, locked and done; the selected one shows its description, progress bar, cost lines (what the lab already has out of what it needs, and what your hold has), requirements, what it unlocks (machines, recipes, belts, abilities, upgrades) and a Start button. Arrows choose, `Enter` starts, the mouse works too. A hint at the bottom says how to deliver the items (port, belt, lab). The pointer is free while it is open; the game keeps running.
- **Build menu** (`B`, `Esc` or `B` closes), docked at the right (about 40 percent of the width, down to the key panel) so the left and the centre of the view stay visible; the research panel (`T`) docks the same way: tabs Logistics (belts, depot, ports), Production (smelter, assembler, cracker, lab), Defence (turret, wall, repair bay) and Structure (module kinds with their cost, power and purpose, and found a station). Each entry shows its quick key, cost (green when your hold can pay, red with what is missing), power use or output, a one-line description and, when locked, which research unlocks it. Arrows move, `Enter` or a click chooses the tool and returns you to flight with it in hand, `PgUp`/`PgDn` change tab. The old palette keys `B`, `U` and `F2`-`F5` are gone: the ore, titanium, nickel, ice, quartz and carbon ports (and the cracker) are reached through the menu only. `B` now always toggles the menu, with or without a tool selected.
- **Ship thrust in the log**: steering sends thrust in steps of 64/1024 and at most ten times a second (a stop is immediate), which keeps saves small; see [structures](prototypes/structures.md#limits). `--load-bench` measures it.
- **Icons and the shared look** ([ui-icons](prototypes/ui-icons.md)): `Gallery.tscn --focus=icons --shot=out.png [--lang=es|en] [--page=1..3]` shows the whole icon set with names; `--ui-shot` also saves `path.research.field.png`.
- **UI screenshots**: `--ui-shot=path [--ui-lang=es|en]` saves `path.research.png`, `path.research.locked.png`, `path.build.png` (Production tab), `path.build.logistics.png`, `path.build.structure.png`, `path.build.defence.png` (the panels docked at the right, with the key panel under them) and `path.bar.png` (the bottom strip and the key panel with a tool in hand), then quits. `--keys-shot=path [--ui-lang=es|en] [--keys-size=1920x1080]` saves the key panel in six contexts (`path.flying.png`, `.build.png`, `.aim.png`, `.walking.png`, `.map.png`, `.menu.png`) plus `.research.png`, `.help.png` and `.info.png` (seated, info panels open), at 1280x720 unless told otherwise.
- **Weapons and the shipyard** ([weapons and shipyard](prototypes/weapons-shipyard.md), [ADR 0032](adr/0032-weapons-as-hardpoint-modules-and-the-shipyard.md)): the ship mines and shoots with hardpoint modules. The starter ship has a mining laser on its nose and a gun on top of the cockpit; without a laser module `M` and the click do nothing ("fit one at a shipyard"), without a gun module `V` cannot pick the guns. `V` switches the weapon group the fire button uses: the mining laser (hold the click on a deposit within the laser's reach, 10 cells from the module, 14 for the Mk2) or the guns (hold the click: they fire at the nearest enemy in range while it is held). Each laser module draws its own beam from the tip of its emitter, mines the same deposit faster (two Mk1 lasers halve the ticks per item, a Mk2 counts 170 percent) and draws 5 power (Mk2: 8). Build a **shipyard** module at a station (`N`, cycle to Shipyard; 24 iron plates, 16 iron ingots, 8 carbon), dock the ship (`U`) and press `F2`: the ship designer shows the ship's grid layer by layer (`Capa -` and `Capa +` change the height; bow at the top), a spinning 3D preview and the module list. Pick a kind and click a free cell next to the ship to add it; click a module to select it and remove, move or upgrade it (laser or gun to Mk2). The panel says whether the design is valid and what it costs (the hold pays first, then the station stock; a removed module refunds half, a moved one is free) and `Aplicar diseño` / `Apply design` sends it in one command. A design needs a cockpit, an engine, a reactor and a cargo module, one connected piece, the docked port kept, and nothing removed that holds a machine. Headless check: `--designer-shot=path` saves the designer (`path`), the applied design (`path.applied.png`) and the refitted ship (`path.ship.png`); `--laser-shot=path` saves two lasers mining a rock (`path`, `path.cockpit.png`).
- **Docking** ([docking](prototypes/docking.md)): the ship moves, a station is fixed. A station (core), a dock module and the ship's cockpit flanks have docking ports. Fly slowly towards a free port of your station: within 45 cells the port shows a marker, its collar a ring of guide lights, and the key panel adds `U` with the distance and your speed against the docking limit. `U` from afar starts the assisted approach (the autopilot flies you to the port, slows down and docks; flying by hand or `U` again cancels it); inside 12 cells and slower than a quarter of the engine speed it docks at once. Docked, the ship is locked to the port (no thrust, no jump), the airlock opens between the two modules and you can stand up and walk into the station; the station's stock shows in the key panel. `,` unloads the hold into the stock (not the fuel), `.` loads from it (fuel first), `U` undocks (aboard the ship; the autopilot pushes off along the port's axis). While docked the reactor burns the stock's hydrogen, the ship repairs three times as fast and the station's shields and defence modules cover it. A station takes no cockpit and no engine. Headless check: `--dock-shot=path` saves `path` (the approach), `path.approach.png`, `path.cockpit.png`, `path.docked.png` (from outside), `path.walk.png`, `path.airlock.png`, `path.station.png` and `path.hud.png`.
- **Space atmosphere**: there is no floor grid any more. The sky is procedural (`game/Ambience.cs`) and comes from the system seed: a nebula band with dark dust lanes, three star layers, a sun disc with a lens streak (the directional light matches it), a far giant star, and two distant bodies lit by that sun (a banded gas giant, often ringed, and a small world). Specks of dust hang around the ship for parallax, a faint haze tints the distance, and above a few cells per second thin motion streaks fade in along the direction of travel. With a cell build tool in hand, a faint 9x9 patch of cell lines shows under the aimed cell, and only on the floor of a fabrication bay (ADR 0031). Look at it with `--structure-demo --demo-big --shot=out.png` or any `--*-shot`.
- Any command-line flag (`--demo`, `--shot=`, `--hud-shot=`, `--structures-shot=`, `--stress=`, `--save-test` and the rest) skips the menu and starts the game directly, as does running `Play.tscn` from the editor. `--menu-shot=path` saves the main menu (`path`), the Settings page (`path.settings.png`), the Controls page (`path.controls.png`) and the pause overlay over the game (`path.pause.png`), then quits. The materials of every model are procedural textures ([materials](prototypes/materials.md)); `Gallery.tscn --focus=materials` shows them all.

## The first ten minutes
1. Follow the steps (full list under `H`; for the first three steps a one-line "Next: ..." hint also shows above the hold bar and fades away afterwards; with the mining laser out and nothing aimed the line says how to aim it). Each one ticks off by itself.
   The game is played in first person: the mouse steers the ship (the cursor is captured): pitch and yaw about the ship's own axes with no limit, and `Z`/`X` (or the left and right arrows) roll it, so you can fly upside down and nothing says which way is "straight" (see [free flight](prototypes/free-flight.md)); `W`/`S` fly along the ship's axis, `A`/`D` strafe, `Space`/`C` go toward the ship's roof and floor. With a build tool in hand, or with `Alt` held, the mouse looks around inside the ship instead (upright in the ship's own frame). (`W`, `A`, `S`, `D`, `Space` and `C` are read as physical keys, so they sit in the same place on AZERTY and other layouts; every other key follows the layout, and the speed keys accept `+`, `=` and the numpad plus). `Tab` frees the cursor for the buttons (click in the game to look again); `Esc` leaves a build tool, then opens the pause menu. The top-down camera is gone. `E` stands you up from the pilot seat; standing, `W`/`A`/`S`/`D` walk inside the ship (`Shift` runs, no jump, `Space`/`C` unused), flight and the autopilot (`M`) are off, and `E` near the seat sits you down again. Repair moved from `E` to `Backspace`. Walking is client-only and limited to your own ship (see [structures](prototypes/structures.md)). Headless check: `--walk-shot=path`.
2. You start seated in the starter ship (cockpit, hull, cargo, reactor, engine; 20 hydrogen for the reactor). It has **no factory and no buildable module**: only a workbench (`F`) and the hold ([ADR 0031](adr/0031-construction-rules-fabrication-bays-and-floor-building.md)). Fly to the brown rock (WASD) until it is within 6 cells, press `M` to take out the mining laser, aim the crosshair at the rock and hold the left click: the beam mines by hand at 2 ore per second for as long as you hold it and stay aimed and in range (let go, look away or fly out of range and it stops; a second `M` stows the laser). The ore goes into the hold. Press `F` to switch the workbench on: it turns ore into ingots (2 s each), press `F` again for plates (2 ingots each, 2 s) and once more for ammo (1 ingot for 4 rounds), and a fourth time to stop it; it makes one thing at a time and the ore, ingot and plate counts move in the hold. Hand mining pauses on its own when the hold reaches 75 % (45 of 60), so there is room to craft and to build; the game says so with a toast and a status line. Spend or move items to continue (there is no command to discard items yet).
3. Make 24 ingots and 8 plates with the workbench, press `N` until the module tool says *Fabrication bay* (24 ingots and 8 plates), aim at a face of the ship beside the hull and click: this is where the factory goes. On its floor (open the build menu with `B`) put an ore port, a smelter, an assembler and a depot and join them with belts; machines and belts are built only on the floor of a fabrication bay (or of a station core, or turrets and walls on the floor of a defence module), and the ghost shows why a cell is refused. Right click on a machine or a belt demolishes it. When the first plate comes out of the assembler (step 5), press `I`, aim at the space beside the ship (the green volume means it can be founded) and click to found a station: it starts with a core module and costs 16 ingots and 12 plates from the hold. A station has no power of its own: add a Reactor module (`N` picks the module tool, pressing `N` again changes the kind) and keep hydrogen in the hold.
4. Open the build menu (`B`): Production has the smelter, assembler, hydrogen cracker and research lab, Logistics has the belts and the ports (ore, ice, quartz, carbon, cargo), Defence has turrets, walls and the repair bay, Structure has the modules (the Fabrication bay is the one that lets you build). Hydrogen is made by a cracker fed ice by an ice port (mine ice by hand first). Look at the ground and the crosshair picks the cell (red when you cannot place there); click to place, for belts press, move the crosshair and release. Right click demolishes a machine or a belt (aim at it, at any height), `R` rotates, `Y` changes the recipe. There is no layer to choose: the ghost snaps to the floor of the bay under the crosshair. Click a machine with no tool to see its status; `Tab` then lets you use its buttons.
5. Build a research lab, feed it plates by belt from an assembler (a port cannot hand out plates), press `T` for the research panel and start Logistics: it lists the cost, what the lab already has, what is required and what it unlocks. Ports are free in structure worlds, so research is about belts, defence upgrades, the jump drive and the advanced materials.
6. When the warning says a wave is coming, turrets can only be built inside a Defence module: add one with `N`, place a turret in it (Defence tab of the `B` menu, or `8`), feed it ammo by belt from an ammo assembler and switch your weapon on (`V`). Each jump to another system (`G`, `J`) costs 5 carbon from the hold, so mine carbon before you leave.

## The goal and the end
The last line of the steps panel is the goal, pinned even when the list is folded: "Goal: survive 10 waves with a station and visit another system (waves N/10, jumps Y/1)". A wave counts as survived once every enemy of it is dead; the goal also needs a station of yours standing (found one with `I` before the last wave) and one completed jump, so the jump drive has to be researched and a second system visited: the research path is part of the win. Until the jump is done, the line adds a hint once the waves are cleared.

- **Victory** ("Station secured"): the goal is met. The game pauses and shows the play time, modules built, stations founded and lost, waves survived, what was mined by hand and by drones, and what was lost. It writes an extra `victory` save. Buttons: Keep playing (endless, the screen never comes back), Main menu, Quit.
- **Scenario games** (everything started from the New game screen): the steps panel at the top right starts with a goals section instead of the goal line: primary goals with a ring (a bar with `current/target` where it counts something), secondary goals with a star, a countdown for goals with a time limit (red under a minute), a failed goal in red with a cross. The guided steps stay under it for the campaign and the levels, and are hidden in a sandbox (free build) without goals. The first story beat of a level opens as a briefing (the scenario's briefing, who is speaking and what they say; the game pauses until you press Intro/Enter); later beats are toasts with the speaker's name. Scenario games end by the scenario's own rules, not the plain wave count:
  - **Victory**: the title, the scenario name, the stars (1 for a win; 2 with the primary goals inside the time bound or with the secondary goals the level asks for; 3 with all of it), a hint for the next star, your time against the best (new record or first completion), each goal as done or failed, and the usual numbers. Buttons: Next level (story levels), Keep playing (campaign, sandbox and custom only; the screen does not come back), Main menu. Winning writes `progress.cfg`; the story levels do not write a `victory` save.
  - **Defeat**: the ship is lost, a primary keep goal failed or a primary time limit passed. Buttons: Retry (the same scenario, rules and seed), Load last save, Main menu. Your autosave and quick save are untouched.
  - Loading a save of another scenario (F9 or the pause menu) reopens the scene on it, like a save of another galaxy. `--end-shot=path` renders a made-up two-star win and a real loss on level 3 (add `--end-legacy` for the old wave-count overlays).
- **Defeat** ("Ship lost", old saves and scripted worlds): the ship's last cockpit fell (there is no respawn in the structures campaign). The play log gets an `Outcome` line. Your autosave and quick save are untouched (a lost world is never autosaved), so Load last save takes you back; or New game, or Main menu (which does not autosave).
- Screenshots of both overlays: `--end-shot=path` saves `path.victory.png` (made-up numbers) and `path.defeat.png` (a real loss).

While a structure is under attack: modules darken and redden with their damage and, below half, throw sparks and smoke with a flickering light; a hit flashes the module and, if it is your ship's, a red vignette pulses; the status block shows the ship's integrity bar; a wave countdown and then the enemy count are shown large at the top; a module you aim at (or one hit in the last seconds) shows its hit points; losing a module or a station raises a toast and an explosion. `--defence-shot=path` renders these (`path`, `path.cockpit.png`, `path.destroyed.png`, `path.station.png`).

## What to try after that
- Hand mining stops at 75 percent of the hold. `Ctrl+Delete` throws the largest stack of spare ore (carbon beyond the jump cost, quartz, titanium or nickel ore, ice while hydrogen is at least 20) into space, with a toast; check that mining resumes afterwards and that iron and hydrogen are never dumped.
- Walls (`9`) in front of the base and the repair button (`Backspace`) during a wave; a repair bay (`0`) fed ingots by belt.
- The defence upgrades in the research panel (`T`), the ports of the Logistics tab of the build menu (`B`; ore, titanium, nickel, ice, quartz and carbon ports are menu-only) and the jump to another system (`G`, `J`) when the status panel says the home ore is running low.
- Play at your normal pace and do not read the docs: where you get stuck is the finding.

## The play log
Every game that is not a demo writes its milestones to a text file as they happen. The path is printed in the console when the game starts, and the folder is:

```powershell
explorer "$env:APPDATA\Godot\app_userdata\Starfoundry Belt Prototype\playlogs"
```

A line has the time in the game (minutes:seconds of simulated time), a kind and a text:

```
2:35  Step       Depot
10:56 Researched core:logistics
12:28 Wave       wave 1 arrived with 2 enemies alive
```

The kinds are `Step` (a guided step), `Researched`, `Wave`, `Loss`, `Jump`, `Tip` (a hint the game showed you) and a last line with how long the hold was completely full. The step names are the ones in the table below.

## What to write down
- Where you got stuck or confused, and what you tried.
- Anything the interface did not tell you (a refusal without a reason, a button you did not find).
- Whether the camera, the autopilot and the drag-to-build felt right.
- Whether the waves felt fair, too slow or too fast, and when you first lost something.
- Whether you ever ran out of ore or ended up with a full hold.
- Send the play log with the notes. If you closed the game, the autosave or quick save can bring you back.

## Known limits
- The numbers in the log are game time, not wall-clock time, and follow the speed you set with `+` and `-`.
- A paused game does not advance the log.

## Hints
After the thirteen guided steps (the panel then says what comes next: scout other systems, get titanium and quartz, build drones, defend) the game teaches the rest with hints that appear when the situation happens, once each and at least 25 seconds apart, as long messages at the bottom: turrets without ammo during a wave, damaged machines (repair with `Backspace`), the first loss without walls, an idle lab, the defence upgrades once Logistics is done, the cargo port once the jump drive is researched and the home ore is low, a station with machines but no Reactor module (`BeltNetwork.StationHasNoReactor`), 15 or more of an ore in the hold with no port for it (structure worlds), and the 5-carbon cost of a jump the first time you open the star map without it. Each hint shown is a `Tip` line in the play log. If a hint came too early, too late or not at all, that is worth noting.

## The HUD
The first-person HUD is minimal by default and shows information by context, never all at once. On screen at rest: the crosshair, the key panel, the notifications and (only when a wave warning or enemies are on) a small alert at the top. Everything else fades in when the context asks for it and fades out again:
- **Seated or flying:** the ship card (top left: hull bar when there are threats, flight readiness, power and hydrogen fuel, structure integrity), the flight readout (top centre: the galactic-frame gizmo, the fixed X, Y, Z axes of the galaxy as seen from your ship, which is not a horizon, and the speed in cells per second; there is no compass: space has no up), the hold strip (bottom left: bar and item counts) and the 3D markers (the selected deposit and the two nearest others, the nearest enemy, stations and docking ports, and the gate toward the system chosen on the star map, each with a name and a distance; off screen, an arrow on the screen edge points the shortest way to turn and says how many degrees).
- **Standing:** nothing but what you aim at. The ship card only appears during a threat. Enemy markers still show.
- **Aiming at something:** that object's card next to the crosshair. A machine gets the target panel (name, role, status, recipe, power, hit-point bar; click it to pin it in the inspector); a belt or a deposit gets a small card with its details; a damaged module shows its hit points. The ship card and the flight readout step aside while you aim at an object.
- **A build tool in hand:** the tool and its cost (bottom left, green when affordable, red when short, grey when locked), the one-line hint and the placement card at the crosshair.
- **`H`: the info panels.** One toggle opens everything the screen normally hides: the full status block (selected deposit, system, threat noise, research, upgrades, structure power), the goals and guided steps (top right) and the hold. `O` folds the steps inside it. The row is in the key panel (`H` Info, lit while open).
- **Notifications:** at most three at a time, repeats grouped as "x3", coloured by category (green production, amber logistics, red threat, white info).
- **Key panel (bottom right):** a compact column of `[KEY] label` rows, drawn as key caps, that changes with what you do or aim at (table below). With the mouse free (`Tab`) a row is clickable and presses its key; the row of the active tool or menu is highlighted, an unavailable row is dimmed and says why in its tooltip (for example "drone bay locked"), and the `1-0` row lists the quick keys with their costs in its tooltip. The build menu and the research panel dock at the right above it. Cards share one look (dark glass, thin edge, soft shadow); the key panel eases in when its context changes.

| Context | Rows |
|---|---|
| Flying, nothing aimed | `B` Build, `T` Research, `G` Star map, `K` Scan, `M` Mining laser (and a "Hold click" fire row once it is out), `F` Workbench, `V` Weapon group (mining laser or guns; with the guns in hand a "Hold the click" row), `F2` Ship designer (only docked at a shipyard), `I` Found station, `N` Module, `Shift` Boost, `Z` `X` Roll, `Alt` Look inside the ship, `E` Stand up, `H` Info, `F1` Help |
| Standing | `WASD` Walk, `Shift` Run, `E` Sit down (dimmed when far from the seat), `B`, `T`, `I`, `N`, `H`, `F1` |
| A build tool in hand | Click Place (belt: Line start, then Line end), `R` Rotate (belts), `Z` `X` Layer (only in worlds without the floor rule), `Y` Recipe (when the machine has several), right click Demolish (module: Remove empty module; a belt line in progress: Cancel the line), `N` Change kind (module tool), `1-0` Quick pick, `B` Menu, `Esc` Cancel |
| Aiming at a machine | `Y` Recipe (its own), Click Inspect / pin, right click Demolish, `Backspace` Repair (dimmed when nothing is damaged), `B` Build |
| Aiming at a belt | right click Demolish, `B` Build |
| Aiming at a deposit | Click Choose, `M` Mining laser, `F7` Drones (dimmed with "drone bay locked" or "no drone bay built"), `B` Build |
| Aiming at a damaged module | its hit points, `B` Build, `N` Module |

| A wave is coming or enemies are alive | a red group on top with `V` Weapons (auto-fire at the nearest enemy) and `Backspace` Repair, plus the rows of the current context |

The rows come from the engine-free `KeyHints` (`src/Starfoundry.Ui`, tests in `KeyHintsTests`): a context is one entry with its condition and its rows, so a new one is easy to add. Every key keeps working as before; the panel only shows and presses them. `Y` with no tool now changes the recipe of the machine you aim at (or the pinned one) instead of the recipe the next placed machine would get.

The bottom hint wraps (up to 1100 px wide) in the room left of the key panel instead of running off the screen, and the star map shrinks so that it, its system list and the Jump button end above the key panel.

## Saving
`F6` saves to the quick slot, `F9` (and Load in the pause menu) loads the newest of the quick save and the autosave, the same rule as Continue in the main menu, and a played game saves itself to an autosave every five minutes of real time. A save is written to a temporary file and renamed over the slot, so a crash mid-save cannot corrupt it; the previous contents are kept beside it (`quicksave.bak.sfsave`, and `autosave.prev.sfsave` for the autosave, so a new game's first autosave does not destroy the previous game's one). A failed load says why in a toast (made with other content, corrupt or not found). The files are in the `saves` folder next to `playlogs` (`%APPDATA%\Godot\app_userdata\Starfoundry Belt Prototype\saves`). A save is the log of what you did and is replayed when loaded, which takes a second or two for an hour-long base ([ADR 0016](adr/0016-saves-are-the-command-log-replayed.md)). If the game says a save cannot be loaded, keep the file and tell me: it means the game changed since it was made. After a load the guided steps are recomputed and a hint may show again. The play log notes the load.

## Sound
The game has procedural audio (synthesised at startup, no asset files; see [audio](prototypes/audio.md)) and **nobody has listened to it yet**. Play with headphones for a while and write down: sounds that are too loud, too quiet, grating or confusing; whether you can tell the engine, the reactor and a working machine apart; whether the wave alarm helps or annoys; whether the calm music is pleasant at 60 % and the tense variant fades in during a wave; whether anything clicks or pops at a loop point. The gains are in `SoundCatalog` (`src/Starfoundry.Ui/Audio/Sfx.cs`). `Godot --headless --path game -- --audio-test` writes every sound to a WAV file and prints its levels; scripted runs (`--demo`, `--*-shot`, `--stress`, `--bench`) are always silent.
