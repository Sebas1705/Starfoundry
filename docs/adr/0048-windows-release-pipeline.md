# 0048. Windows release pipeline: VERSION file, pack beside the exe, resources stamped by the Win32 API, Inno Setup installer, draft-only release workflow

- Status: proposed
- Date: 2026-11-28
- Area: tooling, release
- Builds on: [ADR 0037](0037-external-assets-policy.md) (credits must ship), [packaging](../packaging.md) (how the game finds its content), [CI](../ci.md) (the `build-and-test` gate stays as it is)

## Context
Until now a Windows build existed only as `tools/package.ps1`, which had never run end to end: the export templates were missing, the export needs a solution file the repository does not have, the icon and the version information were empty and there was no installer, checksum or release process. The owner asked for a pipeline that turns a checkout into the exe and an installer with one command, locally and in CI, without publishing anything by itself.

## Decision
- **One source of the version: the `VERSION` file** (semantic version, `0.1.0` to start). `Directory.Build.props` copies it into the assembly version of every project, `Starfoundry.Ui.BuildInfo` reads it back, and the game shows it in the main menu, on the Credits page and in the window title. The release scripts, the installer and the workflow read the same file; a tag `vX.Y.Z` must equal it or the workflow fails. A test (`BuildInfoTests`) keeps the file and the built assembly in step.
- **The pack stays beside the exe** (`binary_format/embed_pck=false`): `Starfoundry.exe`, `Starfoundry.console.exe`, `Starfoundry.pck` and the `data_*` folder with the C# assemblies. An exe with an embedded pack cannot have its resources rewritten and is harder to sign; a separate pack costs nothing for an installer or a zip.
- **Icon and version information are stamped by `Set-ExeResources.ps1` with `BeginUpdateResource`/`UpdateResource`**, not by Godot's rcedit option. rcedit is a separate third-party executable that must be downloaded and registered in the editor settings of every machine and runner; the Win32 API needs nothing. The preset keeps `application/modify_resources=false` and the metadata fields filled in for anyone who prefers rcedit. The icon is our own drawing, generated by `tools/release/make-icon.ps1` (nothing to credit) and committed.
- **What ships is decided by the preset**: `all_resources` plus `content/*`, `assets/credits.tsv`, `assets/audio/*` and `assets/fonts/*` (licence texts included), minus `*.uid`, `*.md`, the dev scenes `Gallery.tscn` and `Main.tscn` and the icon source. `content/` is copied into `game/content` for the export, as in `docs/packaging.md`. The build script then lists the pack and fails when a required file is missing or a dev-only file is in. Docs, tools, tests and C# sources are never in the pack.
- **A throw-away `game/Starfoundry.Game.sln`**: the exporter requires `<assembly>.sln` beside the project, but a permanent one would make `dotnet build game` ambiguous (a folder with a project and a solution). The script creates one for the export and deletes it; it is git-ignored.
- **Licences ship with the build**: `LICENSE.txt`, a `THIRD-PARTY-NOTICES.txt` generated from `ASSETS.md` (the source of the in-game Credits page, so the two cannot drift), the font licence texts in `licenses/`, and the installer shows `LICENSE.txt` on its licence page.
- **Installer: Inno Setup 6** (free, one script, Spanish and English wizards by the Windows language like the game). Per-user by default (`PrivilegesRequired=lowest`, `%LOCALAPPDATA%\Programs\Starfoundry`, no administrator rights; the wizard can switch to all users), Start Menu entry, optional Desktop shortcut, Apps & features entry, a fixed `AppId` so a newer installer upgrades in place and deletes the old assemblies first. Saves and settings live in `%APPDATA%\Godot\app_userdata\Starfoundry Belt Prototype`, outside the install folder, and neither the upgrade nor the uninstaller touches them. The scripts never install Inno Setup silently: they print what and from where, and only `-InstallInnoSetup` runs `winget install --id JRSoftware.InnoSetup` (or `choco install innosetup`).
- **Downloads are explicit and verified.** Missing export templates or Godot make the build print the exact official asset (name, size, source) and exit 2; `-InstallTemplates` and `-InstallGodot` download from the `godotengine/godot-builds` release only, check the size against the GitHub API and the SHA-512 against the release's `SHA512-SUMS.txt`, and unpack only the Windows x86_64 templates.
- **Verification is part of the build.** A headless smoke test runs against the exported folder and again against the installed copy with `APPDATA` redirected to a temp folder: the main menu scene starts and quits, `--self-check` (new, in `MainMenu.SelfCheck.cs`) confirms the content, scenarios, credits data, fonts with their licences and a model are inside the pack, and `--blueprint-check` starts the game scene from the packaged content and runs its PASS/FAIL checks. `test-installer.ps1` installs silently into a temp folder, runs that smoke test, upgrades in place, uninstalls silently and checks the folder, the registry entry and the Start Menu entry are gone.
- **CI: `.github/workflows/release.yml`**, started by `workflow_dispatch` or a tag `v*.*.*`, on `windows-latest` only (never the self-hosted PC). It restores, runs the fast tests, runs the build script with the three `-Install*` switches and `-TestInstaller`, caches NuGet, Godot and the templates, and uploads the zip, the setup exe and `SHA256SUMS.txt` as artifacts. For tags only a second job creates a **draft** GitHub Release; nothing is published, tagged or released automatically. `ci.yml` and its `build-and-test` gate are untouched.
- **Signing is an optional hook** (`sign.ps1`): it runs only when the documented `SF_SIGN_*` secrets exist (Azure Trusted Signing or a `.pfx`) and otherwise reports that the artifacts are unsigned. No certificate, key or secret is in the repository.
- **Versioning and changelog**: conventional commits drive the bump (`feat` raises the minor, `fix` the patch, a breaking change the major; while the version is below 1.0 a breaking change raises the minor); `CHANGELOG.md` follows Keep a Changelog and is edited by hand in the pull request that makes the change.

## Consequences
- One command (`.\tools\release\build-windows.ps1`) gives a verified exe folder, a zip, an installer and their checksums under the git-ignored `artifacts/`, and the same command is what CI runs, so a local success predicts a CI success.
- The first run on a machine needs the export templates (about 1.2 GB to download, about 220 MB kept) and, for the installer, Inno Setup; both are one explicit switch away.
- The exe is large (the mono template is about 110 MB) and unsigned. Windows SmartScreen will warn about an unsigned installer from a new publisher until it builds reputation or is signed; `docs/release.md` says what signing costs.
- The release workflow can only be validated by running it (`workflow_dispatch`) after it is on the default branch; it was reviewed but not executed before the merge.
- Open: the Godot engine's own third-party licence text is only linked from the notices, not bundled; the packaged `--agent` playthrough (Godot MCP bridge) cannot attach to an export, so the packaged smoke test substitutes `--blueprint-check`; there is no auto-update, Steam, itch.io, Linux or macOS build yet (`docs/release.md` lists them as future options).

## Alternatives considered
- Embedding the pack in the exe (single file): rejected, resources cannot be rewritten afterwards and signing is more fragile.
- rcedit for icon and metadata: rejected for the extra download and per-machine editor settings; the preset fields remain for anyone who wants it.
- WiX or MSIX instead of Inno Setup: more power (MSI policies, Store), much more ceremony, and MSIX needs a signing certificate to install at all. Inno Setup does per-user installs, two languages and silent flags in one text file.
- A permanent `game/Starfoundry.Game.sln`: breaks `dotnet build game` (two build files in one folder).
- Releasing automatically on every tag: rejected, the owner approves releases; the workflow only drafts.
