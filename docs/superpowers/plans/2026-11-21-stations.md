# Stations as build volumes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In the campaign, structures can only be built inside a station made of player-placed modules, and ore reaches the station through the ship's cargo port.

**Architecture:** A world setting `StationRules` (stored in the log header; false keeps today's behaviour so old tests, logs and the balance bot are unchanged) adds per-player station modules on an 8 x 8 x 4 cell grid, the commands `PlaceModule` and `RemoveModule`, and placement checks. The engine-free UI layer and the Godot game show modules, a palette entry and new guided steps.

**Tech Stack:** C# 12 / .NET 8 (`src/Starfoundry.Sim`, `src/Starfoundry.Ui`, xUnit), Godot 4.7.2 Mono (`game/`), content in `content/core.json`.

**Spec:** [docs/superpowers/specs/2026-11-21-stations-design.md](../specs/2026-11-21-stations-design.md)

## Global Constraints
- Everything committed is in English; UI strings in `Loc.cs` as Spanish and English; the Loc tests scan keys.
- Commits use the user's own git identity, NO `Co-Authored-By` or "Generated with" trailers, never `--no-verify`.
- The simulation stays deterministic and integer only; stations change only through commands.
- With `StationRules` off, every existing test (401) and the three `BalanceTests` pacing tests must give identical results; old logs and saves still load (read as rules off).
- Module size 8 x 8 x 4 cells, one constant (`StationRules.ModuleX/Y/Z` or similar); modules are aligned to multiples of the module size.
- Build range 24 cells from the ship still applies on top of the station rule.
- Branch `feat/stations` from `main`; open the PR and merge when CI is green (standing permission for this repository). The owner does not want live play tests this round: verify with build, tests and headless screenshots.

## Review Focus
- Placing a belt or machine that straddles a module edge: rejected unless every covered cell is inside a module.
- Removing a module that would split the station, or that holds a machine or belt: refused with a clear reject, never silently deleting the machine.
- Two modules requested at the same coordinate, or a module coordinate far outside the world limits: rejected, never throws.
- Loading an old save or log with the new code, and a station-rules save with old code semantics: old loads as rules off; a content hash change still refuses.
- A hold that cannot afford the core: the ghost says why and the sim rejects with the missing item reported, hold unchanged.
